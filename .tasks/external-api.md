# External read-only API

## Goal and scope

- Design a read-only `/external` API for system-to-system integrations.
- Cover employees, overtime summaries, resource allocation analytics, and projects.
- Authenticate a pair of external system and HR Easy acting user.
- Restrict `/external/**` with one nginx IP allowlist, with localhost-only access by default.
- Implement the approved backend API and nginx allowlist without new persistence or Vue UI.

## Decisions

- Use a dedicated stateless Spring Security chain for `/external/**`.
- Use random opaque Bearer tokens generated by an HR Easy script; external systems never receive a signing key.
- Store only each token's SHA-256 hash and its external-system/acting-user binding.
- Generate one nginx allowlist for `/external/**` from comma-separated `HREASY_EXTERNAL_ALLOWED_IPS`.
- Reuse existing application services and their authorization checks; allocation analytics requires the acting user's `resource_allocation_read` permission.
- Reuse the existing web response shapes in v1 to keep the implementation small.
- Keep overtime summaries grouped by date/project; workstream is exposed only by the detailed employee report API.
- Expose GET operations only. Token issuing, integration administration UI, writes, rate limiting, and response pagination are outside v1.
